# S3 storage (Garage)

Object storage (manga cover images, etc.) is backed by
[Garage](https://garagehq.deuxfleurs.fr/), an S3-compatible object store,
run locally via the `garage` service in `docker-compose.yml`. Its
configuration lives in `garage.toml` (repo root).

## One-time cluster setup

Garage does not bootstrap its cluster layout, bucket, or access keys from
`garage.toml` — this must be done once per environment after the container
first starts.

```bash
docker compose up -d garage

# Get this node's ID (the part before the @)
docker compose exec garage /garage node id -q

# Assign it to the (single-node) cluster layout and apply
docker compose exec garage //garage layout assign -z dc1 -c 1G <node-id>
docker compose exec garage //garage layout apply --version 1

# Create the bucket and an access key, then bind them together
docker compose exec garage //garage bucket create manga
docker compose exec garage //garage key create manga-app-key
docker compose exec garage //garage bucket allow --read --write --owner manga --key manga-app-key

# Second bucket for user-generated EPUBs — reusing the same key keeps local
# setup simple; use a dedicated key in production if you want separate
# quotas/retention policies.
docker compose exec garage //garage bucket create user
docker compose exec garage //garage bucket allow --read --write --owner user --key manga-app-key
```

The `key create` output prints a Key ID and Secret Key — copy them into
`.env` as `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` (see `.env.sample` for
the full list of S3 variables: `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`,
`S3_USER_BUCKET`, `S3_FORCE_PATH_STYLE`).

On Windows with Git Bash, prefix these commands with `MSYS_NO_PATHCONV=1`,
otherwise `/garage` gets mangled into a Windows path by Git Bash's automatic
path conversion.

## S3Service (`api/src/s3/`)

- `s3Client.ts` — the `S3Client` `Context.Tag` and its `Layer` (`S3ClientLive`),
  wrapping the AWS SDK `S3Client`, configured from `appConfig` (`s3Endpoint`,
  `s3Region`, `s3Bucket`, credentials, `s3ForcePathStyle`). Follows the same
  shape as `redis.ts`.
- `s3.service.ts` — `S3Service` (`Effect.Service`), scoped to the configured
  bucket:
  - `upload(key, body: Uint8Array, contentType?)` — puts an object.
  - `download(key)` — returns the object's bytes (`Uint8Array`), or fails
    with `S3ObjectNotFound` if the key doesn't exist.
  - `list(prefix?)` — lists immediate children of a prefix (S3 has no real
    folders), returning `{ files, folders }` where `folders` are the
    `CommonPrefixes` one level down (e.g. `list("covers/")` returns
    `covers/foo.jpg` in `files` and `covers/subdir/` in `folders`, not
    anything nested deeper).
  - `getUrl(key, expiresInSeconds?)` — returns a presigned GET URL (default
    1h expiry, via `@aws-sdk/s3-request-presigner`). Used to expose bucket
    content to the frontend without making the bucket public.
  - `fetchAndUpload(key, url)` — fetches `url` via `HttpClient` and streams
    the response straight into `upload`, retrying the upload with an
    exponential backoff (200ms, 400ms, 800ms, 1.6s) to absorb transient S3
    hiccups. Fails with `ImageFetchFailed` if the fetch itself fails. Used to
    ingest manga cover images and pages without round-tripping bytes through
    the caller.

Per [error handling](error.md), `S3ObjectNotFound`, the generic `S3Error`
(wraps any other SDK/network failure), and `ImageFetchFailed` are domain
errors: they're declared in `s3.service.ts`, added to the `DomainError`
union in `appError.ts`, and mapped in `toHttpError` (`error.ts`) —
`S3ObjectNotFound` → `NotFoundError`, `S3Error`/`ImageFetchFailed` →
`InternalServerError`.

The `covers/...` keys stored in `mangas.path` are generated by
`MangaProviderService` (`manga/mangaProvider.service.ts`): when fetching a
manga from AniList, it also downloads the cover image and uploads it via
`S3Service.upload` under `covers/<anilistId>.<extension>`.

The raw `path` key never leaves the API: `MangaService` (`manga.service.ts`)
resolves it to a presigned URL via `S3Service.getUrl` and exposes it as
`coverUrl` on the `Manga` HTTP schema (`manga.domain.ts`).

Not built yet: no controller/routes expose either service over HTTP — see
`good-pratices.md` conventions for how to wire a new controller when that's
needed.
